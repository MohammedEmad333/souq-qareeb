# سيناريو مناقشة مشروع سوق قريب

**المدة المقترحة:** 10–15 دقيقة.  
**البيئة الأساسية:** https://souq.edubridge.win (الموقع المنشور على Oracle).  
**بديل اختياري:** LocalWP للعرض عند ضعف الإنترنت، **ليس مطلوبًا بحد ذاته**.

## التحضير قبل مشاركة الشاشة

- افتح المتصفح على الموقع المنشور وتحقق من الرئيسية والمتجر وحساب المدير.
- جهّز نافذتين مختلفتين: زائر/Customer تجريبي ومدير.
- استخدم **بيانات تجريبية فقط**، ولا تعرض بريدًا شخصيًا أو رقم هاتف حقيقيًا أو أسرار Stripe.
- جهّز إعلان اختبار بصورة مرخصة أو من ممتلكات الفريق. لا تستخدم أرقام اتصالات أشخاص حقيقيين.
- إن تعذر الدخول إلى Stripe أثناء الجلسة، اعرض لقطة من اختبار Sandbox سابق بعد إخفاء بيانات العميل ومعرّف رابط الطلب؛ لا تدّعِ تنفيذ دفع مباشر.
- احتفظ بخطة رجوع: الصفحة الرئيسية، المتجر، ولقطات لمسار `pending` ثم `published`.

## إجابات أسئلة متوقعة

**لماذا WordPress بدل تطبيق من الصفر؟** لأنه يوفر إدارة المنتجات والحسابات والأساس التجاري، فيما طور الفريق واجهة ووظائف مراجعة وإعلانات وصلاحيات خاصة.

**هل يُنشر إعلان Customer فورًا؟** لا، يُحفظ `pending` حتى يوافق مدير المتجر.

**هل يسمح النظام بالتبرع والتبديل عبر الدفع؟** لا؛ يُعرضان كإعلانات للتواصل، وليس كطلبات سلة.

**هل Stripe دفع حقيقي؟** لا؛ اختبار **Test Mode / Sandbox** فقط، والحماية تمنع عمليات الشراء العامة.

**هل LocalWP شرط؟** لا وفق توضيح المشرف للفريق؛ هو بديل تطوير اختياري، والعرض الأساسي من رابط الإنتاج.

**هل كل اختبارات الإنتاج اكتملت؟** لا؛ HTTP والوظائف الأساسية/اختبار Sandbox موثقة، لكن البريد والاسترجاع والمعاينة البصرية وبعض سيناريوهات إساءة الاستخدام تحتاج قبولًا مستقلًا.

## احتياطات العرض

لا تعطل حارس الدفع، ولا تنفذ تغييرات عشوائية على قاعدة الإنتاج، ولا تُظهر `wp-config.php` أو `.env`. إذا استخدمت حساب مدير، لا تعرض بيانات عملاء حقيقيين في شاشة مسجلة. اختم بميزة واحدة تعمل كاملة، لا بسرد ميزات مخطط لها.
