# حزمة تسليم مشروع «سوق قريب»

**تاريخ الإعداد:** 4 نوفمبر 2026  
**المشروع:** منصة تجريبية مجتمعية للأغراض المستعملة في غزة  
**الرابط المنشور:** https://souq.edubridge.win  
**المصدر:** https://github.com/MohammedEmad333/souq-qareeb

## 1. الفكرة والمشكلة

يساعد «سوق قريب» سكان غزة على الاستفادة من أغراض مستعملة عبر **البيع أو التبديل أو التبرع**، بدل بقائها غير مستعملة. يجمع الموقع العرض والبحث والحساب والإدارة في واجهة عربية متجاوبة.

## 2. المستخدمون والأدوار

- **الزائر:** تصفح المنتجات المنشورة، البحث والتصفية، مشاهدة التفاصيل.
- **العميل:** حساب WooCommerce موحد، تقديم إعلان مع صور وبيانات وحالة وسعر/تواصل، متابعة حالة «إعلاناتي»، تعديل حقول مسموحة، سحب الإعلان.
- **المدير:** مراجعة الإعلانات المعلقة، قبولها أو رفضها، إدارة منتجات WooCommerce.
- **اختبار الدفع:** المدير وحده يمكنه تجربة Stripe Sandbox عند تفعيل البوابة ووضع الاختبار؛ لا يُسمح للعملاء بطلبات دفع حقيقية في العرض الأكاديمي.

## 3. التقنيات

| الطبقة | التقنية |
| --- | --- |
| إدارة المحتوى والمتجر | WordPress + WooCommerce |
| منطق التخصيص | PHP، قالب مخصص، MU plugins |
| البيانات | MariaDB |
| التشغيل | Docker Compose على Oracle Cloud |
| النشر العام | HTTPS عبر البنية الحالية للموقع |
| الفحص المستمر | GitHub Actions لملفات PHP وCompose وأدوات النشر |
| التطوير الاختياري | LocalWP أو أي بيئة WordPress مستقلة؛ غير مطلوب لتسليم الموقع المنشور |

## 4. تدفقات العمل الأساسية

1. **تقديم الإعلان:** Customer يسجل الدخول → يختار بيع/تبديل/تبرع → يرفع صورًا ويملأ الحقول → يرسل → `pending`.
2. **المراجعة:** المدير يرى الإعلان وبياناته → يوافق/يرفض → المنشور فقط يظهر للزوار.
3. **التعديل والسحب:** صاحب الإعلان يعدل البيانات المسموحة، ويعود المنشور إلى المراجعة؛ أو يسحبه فلا يظهر.
4. **الشراء التجريبي:** منتج مؤهل للسلة → checkout يعرض الإجمالي → مدير فقط مع Stripe Test Mode يمكنه تنفيذ عملية Sandbox. **لا تستخدم بطاقة أو مفاتيح إنتاجية.**

## 5. ما أنجز وتحقق

- على نسخة LocalWP المستقلة: تم اختبار حساب Customer، إرسال إعلان بصورة، ظهوره معلقًا، موافقة المدير، وظهوره للزائر، والسلة بإجمالي 50 شيكلًا بعد إصلاح تنسيق السعر.
- على الإنتاج سابقًا: سجل اختبار Stripe Sandbox ناجحًا بحساب المدير، مع حالة طلب مدفوع، ومعرّف معاملة، ووصول طلبات Stripe webhook باستجابة HTTP 200.
- في 4 نوفمبر 2026: أكد فحص مالك خادم Oracle تشغيل الحاويتين وإرجاع HTTP 200 للروابط العامة الستة.
- إصدار المصدر `455a5dead1d5` (3 نوفمبر 2026) اجتاز ست فحوصات GitHub Actions. هذه الأدلة لا تعني اكتمال تدقيق الأمان أو نجاح البريد أو اختبار بصري حديث للنسخة المنشورة.

راجع [سجل نتائج الاختبار](QA_EVIDENCE_AR.md) مع الفصل بين **ناجح** و**بانتظار التحقق**.

## 6. إعادة التشغيل أو النقل

1. خذ نسخة احتياطية من البيانات وملفات `wp-content` من خادم الإنتاج. لا تدخل الأسرار في Git.
2. شغّل Compose بملف `.env` خاص مع `DB_PASSWORD` و`DB_ROOT_PASSWORD`.
3. ثبّت/فعّل WooCommerce وStripe الرسمي **عند الحاجة لاختبار Sandbox فقط**.
4. انشر القالب وإضافات MU والصور المعتمدة داخل مجلدات WordPress الفعلية (Compose يستخدم named volumes).
5. اربط صفحات Shop وCart وCheckout وMy Account وأنشئ صفحة `add-listing`، وأعد حفظ Permalinks.
6. اختبر البيانات والصلاحيات والأمن والواجهة قبل توجيه المستخدمين. لا تستورد بيانات العملاء إلى بيئة عرض عامة.

## 7. ضوابط الأمان والخصوصية

- مراجعة إدارية قبل النشر، وفحص ملكية الإعلان وnonce عند تعديله/سحبه.
- حدود لصيغ وحجم وعدد الصور المرفوعة؛ تحقق إضافي تشغيلي مطلوب لإساءة الاستخدام.
- حارس الدفع `souq-demo-checkout.php` يرفض الدفع العام والمحاولات غير المسموحة، ولا يعتمد على إخفاء زر الواجهة وحده.
- لا تحفظ مفاتيح Stripe أو بيانات عملاء أو مرفقاتهم في المستودع أو الشرائح العامة.
- لا تُنشئ طلبات بيع حقيقية خلال العرض.
