# مراجعة نهائية للإنتاج — سوق قريب

**المقصود:** فحص قراءة فقط للصفحات والحاويات والإعدادات الظاهرة ووجود ملفات النسخ الاحتياطية، من دون إطلاق دفعات شراء، إرسال رسائل بريد أو تعديل بيانات.

## 1) تحديث نسخة المصدر

على **سيرفر Oracle** (وليس Omarchy)، من مجلد المشروع:

```bash
cd ~/souq-qareeb/source
git pull --ff-only origin main
bash -n scripts/production-readonly-audit.sh
bash scripts/production-readonly-audit.sh
```

الأوامر أعلاه لا تعيد نشر الموقع ولا تغير إعداداته. يجب تشغيلها بواسطة مستخدم لديه صلاحية Docker.

## 2) ماذا يراجع السكربت؟

- تشغيل حاويتي WordPress وMariaDB.
- استجابة ست صفحات عامة برمز HTTP 200.
- إتاحة خمس صور هوية بصرية متوقعة برمز 200 ونوع محتوى `image/*`.
- قراءة اسم القالب وحالة WooCommerce والعملة ودقة السعر ووضع Stripe التجريبي ووجود ملف الحماية، **من دون طباعة مفاتيح Stripe**.
- حصر ملفات backup المحتملة ضمن المسار المحدد من دون محاولة استعادتها.
- رصد وجود إضافات بريد مرتبطة بالاسم فقط؛ لا يعدّ هذا اختبار وصول رسالة.

يمكن تخصيص المتغيرات `SOUQ_URL` و`SOUQ_WP_CONTAINER` و`SOUQ_DB_CONTAINER` و`SOUQ_BACKUP_DIR` حسب البيئة.

## 3) ما لا يستطيع إثباته الفحص

- نجاح إعادة تعيين كلمة مرور: يحتاج حسابًا تجريبيًا فعليًا واختبار استقبال الرسالة.
- موثوقية النسخ الاحتياطية: تحتاج تجربة استعادة في **staging معزولة**.
- أمن المسارات الخاصة: يحتاج حسابَي Customer للتأكد من منع تعديل إعلانات الغير.
- واجهة الهاتف: تحتاج لقطات أو فحص بصري في المتصفح على شاشات متعددة.
- Stripe: عدم إظهار مفاتيحه أو تنفيذ الدفع لا يعني فشل البوابة؛ يُستند إلى الاختبار السابق أو يعاد الاختبار في وضع Sandbox فقط.

## 4) إغلاق بند صور الهوية

صور القالب الأصلية **موجودة بالفعل لدى صاحب المشروع في نسخة LocalWP**، لكنها ليست ضمن Git. على جهاز Omarchy:

```bash
cd ~/souq-qareeb-source
git pull --ff-only origin main
bash scripts/collect-brand-assets.sh \
  "$HOME/Local Sites/souq-qareeb-review/app/public/wp-content/themes/souq-qareeb/assets/images"
git status --short
```

لا ترفع أي صور مصدرها `wp-content/uploads` أو مستخدمون دون إذن. بعد فحص الصور والمصدر، أنشئ فرعًا مستقلًا وPR لإدراج الأصول المعتمدة.

## 5) فحص البريد النهائي يدويًا

- من مدير WordPress، تأكد من طريقة إرسال البريد (SMTP موثوق أو مزود بريد) من دون نشر كلمة المرور أو API key.
- من حساب تجريبي **فقط** جرّب «نسيت كلمة المرور» وتحقق من استلام الرسالة وصحة رابط الاستعادة.
- وثّق النتيجة وتاريخها، ولا تعرض بيانات المستخدمين الحقيقيين في لقطات التسليم.

## 6) التوثيق

ضع نتائج الفحص في [سجل QA](QA_EVIDENCE_AR.md) مع عدم وصف أي بند بأنه ناجح لمجرد أن السكربت لم يُظهر خطأ. احتفظ بالنتائج التشغيلية الحساسة خارج GitHub.
