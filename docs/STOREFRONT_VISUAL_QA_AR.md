## الملفات

- `wordpress/themes/souq-qareeb/style.css` و`assets/css/storefront.css` داخل القالب.
- `assets/js/menu.js` لسلوك قائمة الهاتف.
- `header.php` و`footer.php` داخل القالب لتعريب التسميات وتصحيح أبعاد الشعار.
- `index.php` لرسالة 404 وحالة فراغ WordPress العامة.

## الفحص الوظيفي المنفذ

- فتح قائمة الهاتف من لوحة المفاتيح والتنقل إلى أول رابط وإغلاقها بـ Escape مع عودة التركيز، على نسختي Before وAfter.
- البحث عن «كرسي» أعاد منتجين، وحفظ مرشح «حالة ممتازة» الاختيار وعرض صفر نتائج، على النسختين.
- إضافة منتج إلى سلة زائر معزولة وظهور سطر المنتج والوصول إلى Checkout برمز 200 على النسختين. تمت تجربة تحديث الكمية، وتفاصيل المحاولات في سجل المتصفح المرفق مع لقطات المقارنة.
- عرض نماذج دخول وتسجيل واستعادة وإضافة إعلان كزائر. يلزم حساب Customer تجريبي وبيئة معزولة للتحقق من إرسال النموذج، رسائل FluentSMTP، رفع الصور وتعديل الإعلان ومراجعته، الطلبات وتفاصيلها، نجاح وفشل Stripe Test Mode، ومسارات التحقق.
- لم يُرسل طلب شراء أو بريد، ولم تُعدّل إعدادات Stripe.

## قبل الدمج والنشر

راجع صور After ونتائج GitHub Actions وكرر مسارات الحسابات والإعلانات والدفع في [Staging](../scripts/STAGING_STOREFRONT.md). بعد اجتيازها، خذ نسخة احتياطية موثقة من قاعدة البيانات وملفات WordPress وقارن ملفات القالب مع الحجم الحي. انشر الملفات المتغيرة فقط واختبر المسارات العامة بعد التحديث. عند فشل فحص، أعد ملفات القالب السابقة من النسخة الاحتياطية وكرر فحص الصفحة المتأثرة. خطوات `git pull` وحدها لا تصل إلى حجم WordPress العامل.

واجهة الزائر خضعت للمراجعة البصرية، واعتماد العرض الأكاديمي الشامل مرتبط بإكمال الفحوصات المسجلة واختبار ما بعد النشر.
